## Приватность (главная рамка)

Сайт публичный (SEO). Два слоя на одном домене:

| Слой | Что | Кто видит |
|---|---|---|
| Публичный | текст статьи (MDX) | все |
| Личный | оценки, мысли, ответы, история чтения, связки с дневником, обогащения | только владелец (вход) + Claude при парсинге базы |

Правила:
- Личный слой НИКОГДА не рендерится в публичном HTML и не индексируется.
- Дневник на сайт не заливается — живёт в файлах `Leva/дневник/`, Claude подтягивает его только на своей стороне при обогащении.
- Обогащения статьи (связки с дневником) — приватны, в `/me`, не в публичный текст.

## Архитектура

- **Auth:** один владелец. Пароль хранится как bcrypt/argon-хэш в env (`OWNER_PASSWORD_HASH`). `/login` проверяет пароль, ставит подписанную httpOnly-куку (JWT, секрет `AUTH_SECRET`, срок ~90 дней). Регистрации/OAuth нет.
- **Гейтинг:** публичное чтение без входа. Middleware защищает `/me/*` и все `POST /api/*` записи — только с валидной кукой владельца. Публичные визиты чтение НЕ трекают (трек только владельца).
- **БД:** Neon Postgres через `@neondatabase/serverless` (HTTP-драйвер, работает из РФ). Тонкий слой параметризованных запросов в `lib/db.ts`, без тяжёлой ORM.
- **Схема:** один `db/schema.sql`, применяется к Neon один раз.

## Модель данных

```
reads       (id, slug, read_at timestamptz, scroll_pct int)
feedback    (id, slug UNIQUE, rating int CHECK 1..5, thoughts text, updated_at)   -- одна редактируемая запись на статью
answers     (id, slug, question_idx int, answer text, updated_at, UNIQUE(slug, question_idx))
enrichments (id, slug, kind text, body text, created_at)  -- связки статья↔дневник, приватно
recall_log  (id, slug, prompted_at, channel text, response text)  -- фаза 3, спейсд-повторы
```

Вопросы к статье задаются заранее в фронтматтере MDX (`questions: ["...", "..."]`). `answers.question_idx` ссылается на индекс в этом массиве.

## Поведение (data flow)

1. **Трекинг чтения:** на странице статьи клиентский компонент при открытии (и при доскролле до конца) шлёт `POST /api/track {slug, scroll_pct}` — только если владелец залогинен. Пишет строку в `reads`.
2. **Фидбэк:** под статьёй (виден только владельцу) — карточка: статус «прочитано N раз · последний DATE», оценка 1-5, поле «мысли», поля ответов на вопросы. Автосейв (debounce) → `POST /api/feedback`, `POST /api/answers` (upsert).
3. **Дашборд `/me`:** таблица статей (читал/сколько/оценка/ответил ли/кусок мыслей/«пора вспомнить»). Командный центр.
4. **Обогащение (делает Claude, не app):** Claude берёт connection string из личной памяти, читает `feedback+answers+reads` и дневник за те же даты, пишет: (а) запись в дневник в голосе Лёвы, (б) `enrichments` со связками. Показывается в `/me`.
5. **Спейсд-повтор (фаза 3):** Vercel Cron/ТГ-бот по интервалам (3д/неделя/месяц от последнего чтения) шлёт в ТГ «помнишь X? вот твой ответ тогда», пишет `recall_log`.
